# Omarchy 4.0.6 compatibility

This review compares Cleaner with released [Omarchy v4.0.6 at `237f1b4071a0bff2296c6d740ba2b9fd695ebfa0`](https://github.com/omacom/omarchy/tree/237f1b4071a0bff2296c6d740ba2b9fd695ebfa0), including the changes in v4.0.5 (`94a8fbc2d67eec5673c7f16b8c5e8a9c8452ffdc`), against the v4.0.4 baseline. The 4.0.x releases are tagged from a release branch that descends from v4.0.0, not from `quattro`. As a result, the earlier [`10f1cbf` comparison](quattro-catalogue-10f1cbf.md) does not describe these releases.

## Hermes and OpenClaw

In v4.0.5, Hermes moved to Hermes Desktop's self-updating checkout under `~/.hermes`. `omarchy-install-hermes-cli` now accepts only `--check`, `--now`, and `--retire-mise`. Any other mode, including `--owns`, prints usage and exits 1 before it does anything. Migration `1790017600` runs `--retire-mise`. That removes the mise-built environment first and then the wrapper that proves the environment is Omarchy's.

Cleaner still sends only `--owns`. On 4.0.5+ the query fails, so Hermes is never offered. This is intended: a leftover wrapper means the migration is still pending, and deleting it would orphan the mise environment. Among releases, the mise-built wrapper and `--owns` existed only in 4.0.3–4.0.4, where the existing ownership path still applies.

OpenClaw (`omarchy-install-ai-openclaw`) and Hermes Desktop are optional *Install > AI* choices with their own `omarchy-remove-ai-*` removers. Neither is a default install, so neither is offered here. The 4.0.6 OpenClaw migration only affects machines with the `openclaw` package.

No change is needed to package removal, privileges, confirmation, wrapper ownership, or binding cleanup for this release.

## Not addressed: 4.5.0-rc1

The 4.5 release candidate, tagged from `quattro` at `03ff1eff3812933f7088484533784d2f63eaf19a`, was inspected but is deferred until 4.5 is final:

- `signed` replaces `xournalpp` in the drop list. `fcitx5-table-extra` and `omarchy-hyprland-titlebars` join the base packages.
- `applications.lua` binds `omacalc` with a plain command string (`o.bind("SUPER + CTRL + Q", "Calculator", "omacalc")`). The single-line matcher only recognizes table dispatchers, so these shortcuts would not be unbound.
- Default CLI tools become lazy mise shims declared in `/etc/mise/conf.d/omarchy-tools.toml`. Migration `1791382872` deletes old `~/.local/bin` wrappers that match a known template. Remove Preinstalls now opts out of all of them at once through `omarchy-mise-default-tools disable`. Cleaner's CLI section would find nothing on a fresh 4.5 install.

## Validation

- The syntax check and all 48 regression tests pass. ShellCheck was not available in this environment.
- The `v4.0.6` snapshot in `catalogues.json` was produced by an extractor that reproduces the existing `v4.0.4` and `quattro-10f1cbf` entries byte-for-byte. Catalogue coverage now includes v4.0.6. The native-desktop test covers every snapshot with native fixtures, including `omarchy-browser`. Offering that desktop without the `Exec` guard fails the test.
- The installed v4.0.6 `omarchy-install-hermes-cli` was run with `--owns` in a disposable home holding a legacy wrapper. It printed usage, exited 1, and left the home unchanged. Cleaner did not offer or remove the wrapper.
- Read-only discovery on an installed Omarchy 4.0.6-1 system matched the expected results:
  - Recognized wrappers were offered.
  - Native binaries and symlinked CLIs were left alone.
  - Already unbound packaged keys were not unbound again.
- No live VM TUI or removal test was performed. A disposable VM configuration was not available.
