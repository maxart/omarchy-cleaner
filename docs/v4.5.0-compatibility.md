# Omarchy 4.5.0 compatibility

Cleaner 3.3 tracks Omarchy's **v4.5.0** release commit
[`ac2690cd7be4f47e4a255f5e2e78d904d436b068`](https://github.com/omacom/omarchy/tree/ac2690cd7be4f47e4a255f5e2e78d904d436b068).
This review compares the actual tagged sources with the cleaner; it does not
claim compatibility with later changes on `quattro`.

## Assessment and implemented changes

| Area | Finding and implementation |
| --- | --- |
| Packages | Add `signed`, the only missing active member of upstream's drop list. Keep `xournalpp` and all earlier offerings. Add commented entries for `fcitx5-table-extra`, `omarchy-hyprland-titlebars`, `omarchy-power-profiles-daemon`, and `xorg-xsetroot`. |
| Default CLIs | Fresh installs declare lazy tools in `etc/mise/conf.d/omarchy-tools.toml`. Offer the declarations as one explicitly labelled whole-set opt-out, alongside independently selectable legacy wrappers. |
| CLI catalogue | Add Kimi, Amp, Devin, Kiro, DeepSeek, Kilo, MiniMax, Command Code, Freebuff, and Qwen. Verify Qwen's binary and command aliases against mise's registry. Update aliases for existing tools without dropping historical package mappings. |
| Bindings | Recognize literal command-string third arguments to `o.bind`, including both Omacalc keys. Leave functions, concatenation, escaped strings, multiline forms, and unknown dispatchers alone. |
| Launchers | The 11 current webapps need no additions. Retain older webapps and Docker/Disk Usage launchers. Native Foot, imv, mpv, and browser entries remain excluded. |
| Fixtures | Reproduce all five existing catalogue snapshots before adding the pinned release, lazy-tool declarations, helper, installer, and bindings. |

## Why the lazy tools are a group

The upstream [default-tools helper](https://github.com/omacom/omarchy/blob/v4.5.0/bin/omarchy-mise-default-tools)
supports opting out of its complete file. It has no per-default opt-out.
Mise's `disable_tools` setting would also block personal and project declarations;
an empty `[tools]` array did not suppress the lower-priority declaration when
checked with mise 2026.11.1. Neither is a safe selective removal API.

The selector therefore offers **Omarchy default CLI tools (all)**. Nothing is
preselected. Its confirmation lists every declaration as a command name and
functional description where known, explicitly including **Node.js and uv**.
Unknown future tools are listed by their complete key. Choosing an individual
legacy wrapper never invokes the whole-set opt-out.

Opt-out uses `omarchy-mise-default-tools disable` with offline shim refresh.
It adds the upstream ignore entry to the user's `miserc.toml`; packaged files,
installed runtimes, caches, and personal/project declarations remain intact.
Legacy wrappers are separate selections and remain unless selected. A tool may
therefore remain available from a personal declaration or retained wrapper.
Selective removal of individual lazy defaults is not supported.

Before the operation, the cleaner rechecks the complete confirmed declaration
list and hashes of the tools file and personal settings. Existing settings get a
unique backup. Symlinks, redirected parent directories, hardlinked settings, and
conflicting personal ignore lists are refused. If the helper fails after its
expected edit, the previous settings are restored and shim refresh is retried.
Unexpected concurrent edits are retained and reported for manual review. A
failed recovery is reported as a failure with the backup location.

Legacy ownership still requires complete known wrapper templates. Hermes keeps
its read-only `--owns` rule; no runtime-retirement or installation command is
introduced. Removing a single wrapper does not promise to hide a same-named lazy
default.

## Validation

Validation on 6 November 2026 used the exact working-tree script and every test
fixture, verified by SHA-256 after transfer. `bash -n` and ShellCheck 0.11.0
passed. **All 94 regression tests passed on the host and inside both guests**,
including the three real-gum selector checks. The validated runtime SHA-256 is
`47f8f3d50109eba91b30e95babedab483b138a039d02fe2d7219b996f61c68f3`.

The official checksum-verified Omarchy **4.5.0-3** guest ran mise 2026.11.0.
Live checks covered:

- Fresh-layout discovery of Signed, the default-tools group, and both Omacalc
  shortcuts, plus complete-template Kimi/Amp leftovers and personalized launchers.
- Real-gum selection cancellation, piped-entrypoint cancellation, mixed-removal
  cancellation, and group confirmation at 40 columns. State comparisons verified
  that cancellation did not change packages, launchers, bindings, or mise settings.
- Actual removal of Signed, Omacalc, Google Photos, and only the selected Kimi
  legacy wrapper. The complete package change matched the confirmed pacman plan.
  Other packages, Amp, custom Codex, the Muse symlink, and lazy defaults remained.
- Whole-set opt-out through the real upstream helper and real `mise reshim`.
  Default shims retired; the independently configured personal Codex declaration
  retained its shim. Personal settings, exact backups, installed data, and cache
  sentinels were checked.
- Exact binding backups, prepended calculator/webapp unbinds, no Hyprland errors,
  unchanged packaged configuration, and no global preinstalls-removed marker.
  The active binding table confirmed that the hardware calculator binding was
  gone. Actual desktop key events exercised the surviving personal calculator
  replacement and computed shortcut. The first key-event attempt was blocked by
  the guest's idle lock; unlocking and repeating the events passed.

A complementary **4.0.6-1** guest passed real selector/confirmation cancellation
and actual removal of Xournal++, Google Photos, and the Codex legacy wrapper.
Unselected packages and wrappers remained; the package plan, binding backup,
packaged configuration, and removal marker were verified.

Both guests were restored to their pre-test disk snapshots. Package sets, exact
bindings, credentials, system services, and desktop health were verified after
restoration; test changes were absent and both guests were shut down. Historical Lua/conf behavior,
unsupported syntax, refusal paths, and induced failures have isolated regression
coverage; no live failure-path or physical calculator-key claim is made. These
checks establish the exercised workflows, not a proof for every possible user
configuration.
