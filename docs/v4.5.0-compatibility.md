# Omarchy 4.5.0 compatibility

Cleaner 3.3 targets [Omarchy v4.5.0 at `ac2690c`](https://github.com/omacom/omarchy/tree/ac2690cd7be4f47e4a255f5e2e78d904d436b068). It was validated on 4.5.0-3 and 4.0.6-1; later Quattro changes need a separate review.

## Release changes

The implementation retains older catalogue entries and adds the following support:

| Area | Change |
| --- | --- |
| Packages | Offer `signed`. Add commented entries for `fcitx5-table-extra`, `omarchy-hyprland-titlebars`, `omarchy-power-profiles-daemon`, and `xorg-xsetroot`; retain `xournalpp`. |
| CLI defaults | Offer 4.5 lazy declarations as one optional group. Retain individually selectable legacy wrappers. |
| CLI catalogue | Add Kimi, Amp, Devin, Kiro, DeepSeek, Kilo, MiniMax, Command Code, Freebuff, and Qwen. Verify command aliases against mise's registry and retain historical package mappings. |
| Bindings | Recognize literal command-string arguments to `o.bind`, including both Omacalc keys. Preserve computed, escaped, multiline, and unsupported forms. |
| Launchers | Keep the 11 current webapps and older entries. Reject native Foot, imv, mpv, and browser overrides. |

Sources: [packages](https://github.com/omacom/omarchy/blob/v4.5.0/install/omarchy-base.packages), [remover](https://github.com/omacom/omarchy/blob/v4.5.0/bin/omarchy-remove-preinstalls), [tools](https://github.com/omacom/omarchy/blob/v4.5.0/etc/mise/conf.d/omarchy-tools.toml), [installer](https://github.com/omacom/omarchy/blob/v4.5.0/bin/omarchy-mise-install), [bindings](https://github.com/omacom/omarchy/blob/v4.5.0/default/hypr/bindings/applications.lua), and [desktops](https://github.com/omacom/omarchy/tree/v4.5.0/applications). ## Why lazy tools use a group

Omarchy's [default-tools helper](https://github.com/omacom/omarchy/blob/v4.5.0/bin/omarchy-mise-default-tools) only supports opting out of the complete declaration file. Mise's `disable_tools` also blocks personal/project declarations; an empty tool array did not suppress inherited defaults in mise 2026.11.1. Neither met the selective-removal requirement.

**Omarchy default CLI tools (all)** therefore lists every declaration at confirmation, including **Node.js and uv**. Known commands receive descriptions; unknown keys remain visible. Selecting an individual legacy wrapper never triggers this group operation.

The group calls `omarchy-mise-default-tools disable` with offline shim refresh. It ignores Omarchy's declaration file while retaining installed tools, caches, personal/project declarations, and unselected wrappers. A retained declaration or wrapper can keep a tool available. Individual lazy defaults cannot be removed separately.

Before mutation, Cleaner rechecks the confirmed list and configuration hashes and backs up existing `miserc.toml`. It refuses symlinked/hardlinked settings, redirected parents, and conflicting ignore lists. If the helper fails after its expected edit, Cleaner restores settings and retries shim refresh; unexpected edits and recovery failures are reported for manual review.

## Validation: 6 November 2026

The runtime from [commit `b463d9e`](https://github.com/maxart/omarchy-cleaner/commit/b463d9e) and its test data were hash-verified after transfer. Syntax and ShellCheck 0.11.0 passed. All 94 tests passed on the host and both guests, including three real-gum selector tests; [GitHub Actions also passed](https://github.com/maxart/omarchy-cleaner/actions/runs/42270534470).

| Environment | Live checks |
| --- | --- |
| Omarchy 4.5.0-3, mise 2026.11.0 | Discovery; selection, piped-entrypoint and final-confirmation cancellation; group confirmation at 40 columns; removal of Signed, Omacalc, Google Photos, and a Kimi wrapper; explicit group opt-out with a personal Codex declaration/shim retained. |
| Omarchy 4.0.6-1 | Selection/confirmation cancellation; removal of Xournal++, Google Photos, and the Codex wrapper. |

State checks verified complete package plans, unchanged unselected/customized files, exact backups, preserved installed data/caches, unchanged packaged config and removal marker, and no Hyprland errors. Active bindings confirmed the hardware calculator shortcut was gone. After unlocking the idle-locked guest, real key events exercised the surviving personal calculator replacement and computed shortcut.

Both guests were restored and shut down after checking package sets, exact bindings, credentials, and service/desktop health. Historical syntax and induced failures have isolated test coverage; physical calculator-key and live failure-path testing were not performed.
